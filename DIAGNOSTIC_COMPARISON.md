# Diagnostic Comparison Feature (Facility vs At-Home)

## Overview

The Diagnostic Comparison feature allows therapists to record facility-based diagnostic assessments and compare them side-by-side with scores generated by the at-home CVAPed system. This gives clinicians a clear view of how a patient's performance in a controlled clinical setting compares to their self-guided practice at home, enabling more informed treatment decisions and progress tracking.

Patients can also view a read-only summary of this comparison on their Health Logs page.

## Components

### Therapist Dashboard — Diagnostic Comparison Tab

A full-featured tab within the existing TherapistDashboard sidebar navigation.

**Key UI Elements:**

| Element | Description |
|---------|-------------|
| Patient search bar | Typeahead search with dropdown, searches by name/email |
| Comparison table | Side-by-side Facility vs Home scores with color-coded deltas |
| Visual bar chart | Horizontal bars (blue = facility, green = home) for each metric |
| Therapist notes card | Displays clinical notes from the most recent assessment |
| Assessment history | Chronological list of all facility assessments with delete capability |
| "Add Assessment" button | Opens modal to enter a new facility diagnostic |

**State Variables Added:**

| Variable | Type | Purpose |
|----------|------|---------|
| `diagComparisonData` | `object \| null` | Comparison results from API |
| `diagPatientDiagnostics` | `array` | All facility assessments for selected patient |
| `loadingDiagComparison` | `boolean` | Loading state for comparison data |
| `showDiagModal` | `boolean` | Controls facility diagnostic entry modal |
| `selectedDiagPatient` | `object \| null` | Currently selected patient |
| `newDiagnostic` | `object` | Form state for facility diagnostic entry |

### Facility Diagnostic Entry Modal

A comprehensive form modal for therapists to record facility assessment results.

**Form Fields:**

| Field | Type | Validation |
|-------|------|------------|
| Assessment Date | `date` | Required |
| Assessment Type | `select` | initial / follow-up / discharge |
| Severity Level | `select` | mild / moderate / severe |
| Articulation R Score | `number` | 0–100 |
| Articulation S Score | `number` | 0–100 |
| Articulation L Score | `number` | 0–100 |
| Articulation TH Score | `number` | 0–100 |
| Articulation K Score | `number` | 0–100 |
| Fluency Score | `number` | 0–100 |
| Receptive Language Score | `number` | 0–100 |
| Expressive Language Score | `number` | 0–100 |
| Gait Stability | `number` | 0–100 |
| Gait Symmetry | `number` | 0–100 |
| Gait Regularity | `number` | 0–100 |
| Gait Overall | `number` | 0–100 |
| Clinical Notes | `textarea` | Optional |

**Behavior:**
- Empty string values are converted to `null` before saving (avoids storing `""` as `0`)
- Scores are grouped into `articulation_scores` and `gait_scores` objects on submission
- Modal closes and comparison auto-refreshes on successful save
- Escape key and overlay click close the modal

### Patient Health Logs — Facility Comparison Card

A read-only card displayed at the top of the Health Logs page when facility data exists.

**Behavior:**
- Fetches comparison on page load via `diagnosticComparisonService.getMyComparison()`
- Only renders if `has_facility_data` is `true` in the response
- Shows each metric as: `Facility Score → Home Score (±Delta)`
- Delta indicators: green for positive improvement, red for regression, gray for neutral/N/A
- Completely hidden when no facility data exists (no empty state shown to patients)

## API Endpoints

### 1. `POST /api/therapist/diagnostics`

Create a new facility diagnostic assessment.

**Auth:** Therapist required (`@therapist_required`)

**Request Body:**
```json
{
  "user_id": "patient_id_string",
  "assessment_date": "2025-01-15",
  "assessment_type": "initial",
  "severity_level": "moderate",
  "articulation_scores": { "r": 72, "s": 65, "l": 80, "th": 55, "k": 70 },
  "fluency_score": 60,
  "receptive_score": 75,
  "expressive_score": 68,
  "gait_scores": { "stability": 45, "symmetry": 50, "regularity": 55, "overall": 50 },
  "notes": "Patient shows improvement in articulation but needs more fluency work."
}
```

**Success Response (201):**
```json
{
  "message": "Diagnostic created successfully",
  "diagnostic_id": "inserted_id_string"
}
```

---

### 2. `GET /api/therapist/diagnostics/<user_id>`

### 5. `GET /api/therapist/diagnostics/<user_id>/comparison`

Computed comparison between the most recent facility diagnostic and the patient's current at-home system scores.

**Auth:** Therapist required

**Query Parameters:**
| Param | Type | Description |
|-------|------|-------------|
| `diagnostic_id` | `string` | Optional — Compare against a specific assessment instead of the latest |

**Success Response (200):**
```json
{
  "has_facility_data": true,
  "facility_diagnostic": {
    "_id": "...",
    "assessment_date": "2025-01-15",
    "articulation_scores": { "r": 72, "s": 65 },
    "fluency_score": 60,
    "receptive_score": 75,
    "expressive_score": 68,
    "gait_scores": { "stability": 45, "symmetry": 50 }
  },
  "home_scores": {
    "articulation": { "r": 85, "s": 70, "l": 90, "th": 60, "k": 75 },
    "fluency": 55,
    "receptive": 80,
    "expressive": 72,
    "gait": { "stability": 50, "symmetry": 55, "regularity": 60, "overall": 55 }
  },
  "deltas": {
    "articulation": { "r": 13, "s": 5, "l": null, "th": 5, "k": 5 },
    "fluency": -5,
    "receptive": 5,
    "expressive": 4,
    "gait": { "stability": 5, "symmetry": 5, "regularity": null, "overall": 5 }
  },
  "assessment_info": {
    "assessment_date": "2025-01-15",
    "assessment_type": "initial",
    "severity_level": "moderate",
    "notes": "..."
  }
}
```

**At-Home Score Sources:**
| Metric | Collection | Field | Normalization |
|--------|-----------|-------|---------------|
| Articulation (per sound) | `articulation_progress` | `overall_mastery` | × 100 (stored 0–1) |
| Fluency | `fluency_progress` | `overall_mastery` | × 100 (stored 0–1) |
| Receptive Language | `language_progress` (mode: receptive) | `accuracy` | × 100 (stored 0–1) |
| Expressive Language | `language_progress` (mode: expressive) | `accuracy` | × 100 (stored 0–1) |
| Gait metrics | `gaitprogresses` | stability, symmetry, regularity, overall_score | Average of all sessions |

---

### 6. `GET /api/diagnostic-comparison`

Patient's own read-only comparison endpoint.

**Auth:** Patient token required (`@token_required`)

**Success Response:** Same shape as endpoint #5 but uses the authenticated user's own ID. No `diagnostic_id` parameter.

## Database Schema

### `facility_diagnostics` Collection

| Field | Type | Description |
|-------|------|-------------|
| `_id` | `ObjectId` | Primary key |
| `user_id` | `string` | Patient being assessed (ref → `users._id`) |
| `assessed_by` | `string` | Therapist who conducted the assessment (ref → `users._id`) |
| `assessment_date` | `datetime` | Date of the facility assessment |
| `assessment_type` | `string` | `initial`, `follow-up`, or `discharge` |
| `severity_level` | `string` | `mild`, `moderate`, or `severe` |
| `articulation_scores` | `object` | `{ r, s, l, th, k }` — per-sound scores 0–100 |
| `fluency_score` | `float` | Overall fluency score 0–100 |
| `receptive_score` | `float` | Receptive language score 0–100 |
| `expressive_score` | `float` | Expressive language score 0–100 |
| `gait_scores` | `object` | `{ stability, symmetry, regularity, overall }` — 0–100 |
| `notes` | `string` | Therapist clinical notes |
| `recommended_focus` | `array` | Areas the therapist recommends focusing on |
| `created_at` | `datetime` | Record creation timestamp |
| `updated_at` | `datetime` | Last update timestamp |

**Indexes:**
- `user_id` — fast lookup of all diagnostics for a patient
- `assessed_by` — lookup by therapist
- `(user_id, assessment_date)` — compound index for chronological queries

**Relationships:**
- `facility_diagnostics.user_id` → `users._id` (cascade delete)
- `facility_diagnostics.assessed_by` → `users._id`

## Behavior Summary

### Therapist Experience

| Action | Result |
|--------|--------|
| Click "Diagnostic Comparison" tab | Tab loads with patient search |
| Search and select a patient | Latest comparison loads if facility data exists |
| Click "Add Assessment" | Modal opens with empty form |
| Fill form and save | Diagnostic saved, comparison refreshes |
| View comparison table | Side-by-side scores with green/red delta indicators |
| View bar chart | Visual representation of facility (blue) vs home (green) |
| Delete an assessment | Assessment removed, comparison refreshes |
| Select different assessment from history | Comparison updates to use that assessment |

### Patient Experience

| Condition | Result |
|-----------|--------|
| Facility data exists | Comparison card shown at top of Health Logs |
| No facility data | Card is completely hidden |
| Positive delta (home > facility) | Green indicator with ▲ arrow |
| Negative delta (home < facility) | Red indicator with ▼ arrow |
| Score not available | Gray "N/A" indicator |

## Design Decisions

1. **Primary placement: Therapist Dashboard sidebar tab.** The diagnostic comparison is fundamentally a clinical tool. Therapists need to enter, edit, and analyze facility data — making the TherapistDashboard the natural home. A dedicated sidebar tab prevents clutter in existing tabs.

2. **Secondary placement: Patient Health Logs card.** Patients benefit from seeing how their at-home practice compares to their facility assessment, but only in a read-only capacity. The Health Logs page already aggregates progress data, making it the ideal location.

3. **Conditional rendering for patients.** The comparison card only appears when `has_facility_data` is `true`. This avoids showing an empty or confusing card to patients who haven't had a facility assessment yet.

4. **Score normalization to 0–100.** Facility scores are entered directly as 0–100. At-home mastery scores (stored as 0–1 floats) are multiplied by 100 at the API level. This ensures consistent comparison without frontend conversion logic.

5. **Delta = Home − Facility.** A positive delta means the patient is performing better at home than at the facility, which is the desired trajectory. This convention is consistent throughout both the therapist and patient views.

6. **Most-recent-first comparison.** By default, the comparison uses the latest facility diagnostic. Therapists can optionally select a specific historical assessment from the history list to compare against.

7. **Empty string → null conversion.** When saving facility diagnostics, empty form fields are converted to `null` rather than stored as empty strings or `0`. This prevents misleading zero scores in comparisons.

8. **No blocking or mandatory workflow.** The diagnostic comparison is entirely optional. It does not gate any therapy features. Patients and therapists can use all existing functionality without ever interacting with this feature.

9. **Gait score averaging.** At-home gait scores are computed as the average across all `gaitprogresses` sessions, providing a holistic view rather than a single-session snapshot.

10. **CSS namespace isolation.** Therapist Dashboard styles use the `.diag-*` prefix. Health Logs styles use the `.fc-*` prefix. This prevents class name collisions with the rest of the application.
